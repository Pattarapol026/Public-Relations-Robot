# AI Reception Robot Platform

ซอฟต์แวร์หุ่นยนต์ประชาสัมพันธ์สำหรับสถานศึกษา — **รุ่น 0.7.0 (AI, เสียงพูด, การมองเห็น, สถิติ และคำสั่งหุ่นยนต์ด้วยเสียง)**

รุ่นนี้มี: ตอบคำถามด้วย Gemini จากฐานความรู้ของสถานศึกษา, พูดคำตอบและคำทักทายด้วยเสียงภาษาไทย (PyThaiTTS), รับคำถามด้วยเสียง (faster-whisper) แบบสนทนาต่อเนื่อง ทั้งภาษาไทยและอังกฤษ, Smart Welcome ด้วยกล้อง OAK-D, จำการ์ดสัญลักษณ์และท่าทางมือ, เก็บคำติชมคำตอบ, สถิติการใช้งานและรายการคำถามที่ยังตอบไม่ได้, ประกาศประชาสัมพันธ์ตามเวลา, หน้าแสดงว่าข้อมูลของสถานศึกษาเข้า AI อย่างไร, หน้าแรกเล่นสื่อประชาสัมพันธ์ที่ Admin เลือก, หน้า Admin จัดการสื่อ ประกาศ ฐานความรู้ เสียง กล้อง และการตั้งค่า, ฐานข้อมูล SQLite, `CommandGateway` และ `MockRobotAdapter`
รุ่น 0.7 เพิ่ม: สั่งหุ่นยนต์ด้วยคำพูด (ท่าแขน การเคลื่อนที่พื้นฐาน การนำทาง), ท่าทักทายเมื่อมีคนเข้ามา และกฎไม่ขยับเมื่อมีคนอยู่ใกล้ — **ทั้งหมดทำงานกับหุ่นยนต์จำลองเท่านั้น**
รุ่นนี้ **ยังไม่มี**: การเชื่อมต่อหุ่นยนต์จริง (V0.8), การจำวัตถุที่นักศึกษาเทรนเอง, ท่าชี้ทางประกอบคำตอบ ดูลำดับทั้งหมดที่หัวข้อ "แผนรุ่นถัดไป"

## ติดตั้งและรันบน Windows

ต้องมี Python 3.12

```powershell
cd D:\robotReception
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip install nvidia-cublas-cu12 nvidia-cudnn-cu12   # ถอดเสียงบนการ์ดจอ NVIDIA (เร็วกว่า CPU ราว 10 เท่า); ไม่ลงก็ใช้งานได้ด้วย CPU
.\.venv\Scripts\python.exe -m pip install pyusb libusb-package   # ไมค์อาเรย์ XVF3800: อ่านทิศทางเสียง (ไม่ลงก็ใช้งานได้ แต่ไม่มีข้อมูลทิศ)
Copy-Item .env.example .env      # ไม่บังคับ — ไม่มี .env ก็รันได้ใน Demo Mode
.\.venv\Scripts\python.exe main.py
```

รันชุดทดสอบ (ไม่ใช้ไมโครโฟนจริงและไม่ดาวน์โหลดโมเดล):

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

**เปิดครั้งแรกต้องต่ออินเทอร์เน็ต** โปรแกรมจะดาวน์โหลดโมเดลถอดเสียง `small` (ประมาณ 460 MB) มาเก็บในโฟลเดอร์ `models/` และโมเดลเสียงพูด (ประมาณ 330 MB) ไปที่ `~/.cache/fastthaig2p` ระหว่างนั้นป้ายมุมขวาบนแสดง "ไมโครโฟน: กำลังเตรียม" และยังใช้การพิมพ์กับปุ่มลัดได้ตามปกติ ครั้งถัดไปโหลดจากเครื่องใน 2–3 วินาทีและไม่ต้องใช้อินเทอร์เน็ต

Windows ต้องอนุญาตไมโครโฟน: Settings → Privacy & security → Microphone → เปิด "Let desktop apps access your microphone"

## ติดตั้งและรันบน Ubuntu

> ขั้นตอนนี้ยังไม่ได้ทดสอบบนเครื่อง Ubuntu จริง (อยู่ในแผน V1.0) โค้ดไม่มีส่วนที่ผูกกับ Windows

```bash
sudo apt install python3.12 python3.12-venv libxcb-cursor0 libportaudio2
cd ai-reception-robot
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
cp .env.example .env
.venv/bin/python main.py
```

- `libxcb-cursor0` จำเป็นสำหรับ Qt 6 บน X11 และ `libportaudio2` จำเป็นสำหรับไมโครโฟน (sounddevice)
- ฟอนต์ไทย (Sarabun) มากับโปรแกรมแล้วใน `ui/assets/fonts` ไม่ต้องติดตั้งฟอนต์เพิ่ม
- การเล่นวิดีโอใช้ FFmpeg ที่มากับ PySide6 หากไฟล์บางชนิดเล่นไม่ได้ให้ตรวจ codec ของไฟล์นั้นก่อน

## การตั้งค่า

| ที่ | ใช้เก็บ |
| --- | --- |
| `.env` (ไม่ commit) | `GEMINI_API_KEY`, adapter, ระดับ log, โฟลเดอร์ข้อมูล, timeout, ขนาดไฟล์สื่อสูงสุด, โมเดลถอดเสียงและความไวไมโครโฟน — ดู `.env.example` |
| `config/app_config.json` | ชื่อสถานศึกษา, รายการตำแหน่งและท่าทางที่อนุญาตให้หุ่นยนต์ทำ, และ **ข้อมูลเริ่มต้น** (ข้อความต้อนรับ ประกาศ FAQ) |
| หน้า Admin → ฐานข้อมูล `data/app.db` | สื่อ, ประกาศ, ฐานความรู้, ข้อความต้อนรับ, เวลาแสดงผล, กำหนดการประกาศ, สถิติการใช้งาน, รหัสผ่านผู้ดูแล, ประวัติการทำงาน |

ข้อความต้อนรับ ประกาศ และ FAQ ใน `app_config.json` ถูกคัดลอกเข้าฐานข้อมูล **ครั้งแรกครั้งเดียว** หลังจากนั้นให้แก้ในหน้า Admin การแก้ไฟล์ JSON จะไม่มีผลกับสามรายการนี้อีก ข้อมูลเริ่มต้นเป็นข้อมูลตัวอย่าง ต้องแก้เป็นของสถานศึกษาจริง

## การตอบคำถามด้วย AI

แต่ละคำถามผ่านสามขั้นตามลำดับ:

1. **ตรงกับรายการในฐานความรู้พอดี** (เช่น กดปุ่มคำถามที่พบบ่อย) → ตอบจากฐานความรู้ทันที ไม่ใช้อินเทอร์เน็ต
2. **คำถามอื่น** → โปรแกรมคัดรายการในฐานความรู้และประกาศที่เกี่ยวข้อง ส่งให้ Gemini พร้อมกติกาว่าให้ตอบจากข้อมูลนี้เท่านั้น ห้ามแต่งข้อมูล ถ้าไม่มีให้บอกว่าไม่มีและแนะนำให้ถามเจ้าหน้าที่
3. **Gemini ใช้ไม่ได้** (เน็ตหลุด, เกินโควตา, ตอบช้าเกิน `GEMINI_TIMEOUT_S`) → ตอบจากรายการในฐานความรู้ที่ตรงที่สุดถ้าตรงชัดเจน ไม่เช่นนั้นตอบว่ายังไม่มีข้อมูล

- **เพิ่มความรู้ให้หุ่นยนต์** ทำที่ Admin → ฐานความรู้ และ Admin → ประกาศ มีผลกับคำตอบถัดไปทันที ไม่ต้องเปิดโปรแกรมใหม่
- **จำบทสนทนา** 3 คำถามล่าสุดของผู้ใช้คนเดียวกัน เพื่อให้ถามต่อเนื่องได้ และลืมเมื่อผู้ใช้เดินจากไปหรือกลับหน้าแรก
- **ภาษา:** ตอบเป็นภาษาเดียวกับคำถาม คำถามภาษาอังกฤษได้คำตอบภาษาอังกฤษ
- **สิ่งที่ส่งออกอินเทอร์เน็ต:** ข้อความคำถาม บทสนทนาล่าสุด และรายการฐานความรู้ที่คัดไว้ ถูกส่งไปยังบริการ Gemini ของ Google เสียงและภาพไม่ถูกส่ง ถ้าไม่ต้องการให้ส่งอะไรเลย ตั้ง `AI_ENABLED=false`
- **Gemini สั่งหุ่นยนต์ไม่ได้:** คำตอบของโมเดลถูกนำไปแสดงและอ่านออกเสียงเท่านั้น
- ทดสอบการเชื่อมต่อได้ที่ Admin → สถานะ → "ทดสอบการเชื่อมต่อ AI" และดูว่าแต่ละคำตอบมาจากทางไหนได้ที่ Admin → ประวัติ (`conversation.answer`)
- ดูว่าคำถามหนึ่ง ๆ ทำให้ข้อมูลรายการไหนถูกคัดและส่งให้ AI ด้วยข้อความอะไร ได้ที่ Admin → AI (ปุ่ม "ถามจริง" ในหน้านั้นไม่นับเป็นสถิติ)
- เปลี่ยนรุ่นโมเดลได้ด้วย `GEMINI_MODEL` ค่าเริ่มต้น `gemini-3.5-flash-lite` ตอบในราว 1 วินาที

## สถิติ ผลตอบรับ และการประกาศตามเวลา

**Admin → สถิติ** สรุปช่วง วันนี้ / 7 วัน / 30 วัน: จำนวนผู้เข้ามาในบริเวณ (จากกล้อง), สัดส่วนที่เข้ามาสนทนา, จำนวนคำถาม, สัดส่วนที่ตอบได้, ความพอใจ (จากนิ้วโป้งและปุ่มบนจอ), เวลาตอบเฉลี่ย, กราฟจำนวนคำถามตามชั่วโมงของวัน และส่งออกเป็นไฟล์ CSV ที่เปิดใน Excel ได้

ตารางด้านล่างของหน้านั้นคือ **คำถามที่หุ่นยนต์ยังตอบไม่ได้ หรือผู้ใช้บอกว่ายังไม่ตรง** เลือกแถวแล้วกด "เพิ่มคำตอบในฐานความรู้" เพื่อกรอกคำตอบ หุ่นยนต์ใช้ตอบได้ตั้งแต่คำถามถัดไป นี่คือวงจรปรับปรุง: ผู้ใช้ถาม → ระบบบันทึกสิ่งที่ตอบไม่ได้ → ผู้ดูแลเติมข้อมูล → ตอบได้

**Admin → กำหนดการ** ตั้งข้อความที่หุ่นยนต์ประกาศเองตามเวลาและวันในสัปดาห์ พร้อมสื่อประกอบบนหน้าแรก (ไม่บังคับ) ถ้าถึงเวลาแล้วมีคนกำลังคุยกับหุ่นยนต์หรือผู้ดูแลกำลังใช้งาน ระบบจะรอจนว่างไม่เกิน 10 นาที เกินจากนั้นข้ามของวันนั้น ปุ่ม "ประกาศเดี๋ยวนี้" ใช้ทดลองได้โดยไม่ต้องรอเวลา

**ข้อมูลที่เก็บ (เปลี่ยนจากรุ่นก่อน):** ตั้งแต่รุ่น 0.6 โปรแกรมเก็บ **ข้อความคำถามและคำตอบ** ไว้ในฐานข้อมูลบนเครื่อง (`data/app.db`) เพื่อให้เห็นคำถามที่ตอบไม่ได้ รุ่นก่อนหน้านี้ไม่เก็บข้อความเลย

- ไม่เก็บเสียง ภาพ ใบหน้า หรือชื่อของผู้ถาม ข้อมูลผู้เข้ามามีเพียงเวลา ระยะใกล้สุด และจำนวนคำถาม
- ผู้ใช้อาจพูดข้อมูลส่วนตัวของตัวเองในคำถามได้ จึงควรติดป้ายแจ้งที่จุดติดตั้งว่ามีการบันทึกข้อความคำถามเพื่อปรับปรุงบริการ
- ตั้ง `LOG_QUESTIONS=false` เพื่อเก็บเฉพาะตัวเลข ไม่เก็บข้อความ (หน้ารายการคำถามที่ตอบไม่ได้จะว่าง)
- ข้อมูลที่เก่ากว่า `USAGE_RETENTION_DAYS` (ค่าเริ่มต้น 90 วัน) ถูกลบเมื่อเปิดโปรแกรม และปุ่ม "ลบข้อความคำถามที่เก็บไว้ทั้งหมด" ลบข้อความได้ทันทีโดยตัวเลขสถิติยังอยู่
- ไฟล์ CSV ที่ส่งออกและไฟล์สำรองฐานข้อมูลมีข้อความคำถามอยู่ด้วย ควรเก็บให้เฉพาะผู้เกี่ยวข้อง
- ผู้ที่ยังอยู่หน้ากล้องตอนปิดโปรแกรมจะไม่ถูกนับเป็นผู้เข้ามา (นับเมื่อเดินออกจากบริเวณ)

## เสียงพูดของหุ่นยนต์

หุ่นยนต์พูดคำทักทายและคำตอบด้วย PyThaiTTS (โมเดล `fastthaig2p`, ทำงานในเครื่อง ไม่ใช้อินเทอร์เน็ตหลังดาวน์โหลดแล้ว)

- ข้อความขึ้นจอก่อน แล้วเสียงตามมาในราว 1 วินาที คำตอบยาวจะเริ่มพูดท่อนแรกระหว่างที่สร้างเสียงท่อนถัดไป
- กด **หยุด** หรือถามคำถามใหม่ หุ่นยนต์หยุดพูดทันที ไมโครโฟนไม่เปิดระหว่างที่หุ่นยนต์พูด
- ข้อความภาษาอังกฤษอ่านได้ แต่เป็นเสียงและสำเนียงของโมเดลภาษาไทย
- เลือกลำโพงและทดสอบเสียงพูดได้ที่ Admin → เสียง ปรับความเร็วด้วย `TTS_SPEED` ปิดด้วย `TTS_ENABLED=false`
- ถ้าโมเดลเสียงหรือลำโพงใช้ไม่ได้ คำตอบยังแสดงเป็นข้อความตามปกติ

## การสนทนาด้วยเสียง

1. กด **เริ่มสนทนา** → สถานะเป็น "กำลังฟัง... พูดได้เลย" และแถบระดับเสียงขยับตามเสียงพูด
2. พูดคำถาม เมื่อหยุดพูดประมาณ 1.2 วินาทีระบบจะถือว่าพูดจบเอง (หรือกด **พูดจบแล้ว**)
3. สถานะเป็น "กำลังคิด..." ระหว่างถอดเสียงและหาคำตอบ แล้วแสดงคำถามที่ถอดได้กับคำตอบ
4. กด **หยุด** เมื่อใดก็ได้เพื่อยกเลิก เสียงที่อัดไว้จะถูกทิ้ง

- **สนทนาต่อเนื่อง:** เมื่อหุ่นยนต์ตอบเสร็จ ไมโครโฟนเปิดรอคำถามถัดไปเองโดยไม่ต้องกดปุ่ม ถ้าไม่มีใครพูดต่อก็หยุดฟังเงียบ ๆ ถ้ามีกล้อง จะฟังต่อเฉพาะเมื่อผู้ใช้ยังอยู่ในบริเวณ ปิดได้ด้วย `VOICE_FOLLOW_UP=false`
- ถ้าไม่มีใครพูดภายใน 6 วินาที ระบบหยุดฟังเองและแจ้งให้ลองใหม่ การอัดหนึ่งครั้งยาวไม่เกิน 20 วินาที
- ถ้าไมโครโฟนหรือโมเดลใช้ไม่ได้ ปุ่มเริ่มสนทนาจะเปลี่ยนเป็นโหมดพิมพ์และบอกสาเหตุ ส่วนอื่นของโปรแกรมทำงานต่อได้
- เสียงถูกถอดเป็นข้อความในเครื่องนี้เท่านั้น ไม่ส่งออกอินเทอร์เน็ตและไม่บันทึกลงดิสก์
- **พูดภาษาอังกฤษ:** กดปุ่ม **English** ในหน้าสนทนาก่อนพูด ระบบจะถอดเสียงเป็นภาษาอังกฤษจนกว่าจะกลับหน้าแรกหรือกดปุ่มอีกครั้ง ค่าเริ่มต้น `STT_LANGUAGE=th` ถอดเป็นภาษาไทย ซึ่งประโยคอังกฤษล้วนจะถอดผิด (คำถามที่พิมพ์ไม่ต้องกดปุ่ม ระบบดูภาษาเอง)
- ความแม่นและความเร็วขึ้นกับ `STT_MODEL`: บน CPU โมเดล `small` ถอดเสียง 7 วินาทีได้ในราว 2 วินาที ถ้าถอดผิดบ่อยให้ลอง `medium` หรือ `large-v3-turbo` (ช้ากว่าและใช้หน่วยความจำมากกว่า)
- ปิดระบบเสียงทั้งหมดได้ด้วย `STT_ENABLED=false`

## หน้าแรก: สื่อประชาสัมพันธ์ที่ Admin เลือก

หน้าแรกคือหน้าประชาสัมพันธ์ พื้นที่ใหญ่ด้านซ้ายเล่นสื่อที่ Admin เปิดใช้งานไว้ (วิดีโอและรูปภาพ วนตามลำดับ) พร้อมประกาศหมุนเวียน ด้านขวาเป็นภาพกล้องขนาดเล็ก ข้อความต้อนรับ และปุ่ม "เริ่มสนทนา"

- **Admin เลือกสิ่งที่เล่น** ที่หน้า "สื่อประชาสัมพันธ์": เปิด/ปิดใช้งานแต่ละรายการ จัดลำดับ และกด "เล่นบนหน้าแรกตอนนี้" เพื่อข้ามไปรายการที่ต้องการ
- **Admin เลือกรูปแบบหน้าแรก** ที่หน้า "ตั้งค่าหน้าจอ" → "หน้าแรกแสดง": สื่อประชาสัมพันธ์และประกาศ (ค่าเริ่มต้น) หรือภาพสดจากกล้องขนาดใหญ่
- ถ้าสิ่งที่เลือกยังไม่มี (เช่น ยังไม่มีสื่อและประกาศ หรือไม่มีกล้อง) หน้าแรกจะแสดงอีกอย่างแทนเอง
- สื่อหยุดเล่นเมื่อเข้าหน้าสนทนา เพื่อไม่ให้เสียงวิดีโอรบกวนไมโครโฟน และเล่นต่อเมื่อกลับหน้าแรก

## กล้อง OAK-D: Smart Welcome

เสียบ OAK-D เข้าช่อง USB 3 แล้วเปิดโปรแกรม กล้องใช้เวลาเริ่มทำงานราว 6–9 วินาที (ครั้งแรกต้องต่ออินเทอร์เน็ตเพื่อดาวน์โหลดโมเดลตรวจจับ) หุ่นยนต์ต้อนรับเป็นสองจังหวะตามระยะของผู้มาติดต่อ:

| ระยะ (ค่าเริ่มต้น) | สิ่งที่หุ่นยนต์ทำ |
| --- | --- |
| ไกลกว่า 3 เมตร หรือเดินผ่าน | เล่นสื่อบนหน้าแรกต่อไป |
| เข้ามาในบริเวณให้บริการ (ใกล้กว่า 3 เมตร นาน 1.5 วินาที) | ทักทาย และเปิดหน้าเมนูบริการ (คำถามที่พบบ่อยและปุ่มสั่งงาน) ยังไม่เปิดไมโครโฟน |
| เข้ามาถึงระยะสนทนา (ใกล้กว่า 1.5 เมตร ตรงหน้า) | เปิดไมโครโฟนรับเสียงและตอบคำถาม โดยไม่ต้องกดปุ่ม |
| ออกไปไกลกว่า 3.6 เมตร หรือไม่เห็นนาน 4 วินาที | ล้างการสนทนา กลับหน้าแรก |

- **ไม่รบกวน:** กล้องไม่ขัดจังหวะคนที่กำลังใช้งานผ่านจอสัมผัส และไม่มีผลกับหน้า Admin
- **ภาพสดบนหน้าจอ:** แสดงแบบกระจกเงา พร้อมกรอบและระยะของแต่ละคน (กรอบสีฟ้าคือคนที่อยู่ในระยะสนทนา)
- **ความเป็นส่วนตัว:** การตรวจจับคนและวัดระยะทำในตัวกล้อง ภาพสดถูกส่งมาที่คอมพิวเตอร์เพื่อแสดงบนจอเท่านั้น โปรแกรมไม่บันทึกภาพและไม่จดจำใบหน้า ถ้าไม่ต้องการให้มีภาพออกจากกล้องเลย ตั้ง `VISION_PREVIEW=false` (การทักทายยังทำงานเหมือนเดิม) ควรติดป้ายแจ้งผู้ใช้ว่าหุ่นยนต์มีกล้อง
- **ไม่มีกล้องก็ใช้ได้:** ถ้าไม่เสียบกล้องหรือกล้องหลุดระหว่างใช้งาน หน้าแรกจะแสดงแบบไม่มีภาพกล้อง โปรแกรมทำงานต่อแบบกดปุ่มตามเดิม และลองเชื่อมต่อใหม่เองทุก 4 วินาที
- แก้คำทักทายได้ที่ Admin → ตั้งค่า ดูสิ่งที่กล้องเห็นและระยะทั้งสามได้ที่ Admin → กล้อง ปรับระยะได้ใน `.env` (`VISION_...`) และปิดได้ด้วย `VISION_ENABLED=false`

## การ์ดสัญลักษณ์และท่าทางมือ

ผู้ใช้โต้ตอบกับหุ่นยนต์ได้โดยไม่ต้องพูดหรือแตะจอ ด้วยการยกการ์ดหรือทำท่าทางมือให้กล้องดู Admin เป็นผู้กำหนดว่าแต่ละอย่างหมายถึงอะไรที่แท็บ **การ์ด/ท่าทาง**

**การ์ด** (สูงสุด 50 ใบ หมายเลข 0–49)

1. Admin → การ์ด/ท่าทาง → "เพิ่มการ์ด" ตั้งชื่อ (เช่น แผนกเทคโนโลยีสารสนเทศ) ข้อความที่หุ่นยนต์จะพูด และเลือกสื่อที่จะแสดงบนหน้าแรกได้
2. เลือกการ์ดแล้วกด "บันทึกภาพการ์ดสำหรับพิมพ์" จะได้ไฟล์ PNG ขนาด A6 ที่มีเครื่องหมายและชื่อการ์ด
3. พิมพ์บนกระดาษด้าน (กระดาษมันสะท้อนแสงทำให้อ่านยาก) แล้วยกให้กล้องดู ถือให้เห็นขอบขาวรอบเครื่องหมายครบ

**ท่าทางมือ** มี 7 ท่า ทุกท่ามีค่าเริ่มต้น Admin เปลี่ยนข้อความหรือการทำงานได้ แต่ละท่ามีสีหน้าของตัวเองบนจอราว 5 วินาที และหุ่นยนต์พูดข้อความตอบออกเสียง

| ท่าทาง | ค่าเริ่มต้น | สีหน้า |
| --- | --- | --- |
| ยกนิ้วโป้งขึ้น | บันทึกว่าพอใจคำตอบล่าสุด (ถ้ามี) แล้วกล่าวขอบคุณ | ตาเป็นดาว ยิ้มกว้าง มีประกายรอบหน้า |
| คว่ำนิ้วโป้งลง | บันทึกว่าไม่พอใจคำตอบล่าสุด (ถ้ามี) แล้วขออภัย | ตาปรือ ปากคว่ำ มีน้ำตาไหล |
| แบมือ | หยุดพูดและหยุดฟัง | หลับตาสงบ |
| สัญลักษณ์ไอเลิฟยู | "ขอบคุณครับ ผมก็รักทุกคนเลยครับ" | ตาเป็นหัวใจ มีหัวใจลอยขึ้น |
| ชูสองนิ้ว | ชวนถ่ายรูป | ขยิบตา |
| กำมือ | ให้กำลังใจผู้แข่งขัน | ตาหยี > < ปากกว้าง มีเส้นพลัง |
| ชี้นิ้วขึ้น | "มีคำถามใช่ไหมครับ" แล้วเปิดไมค์ฟัง (ถ้ากล้องเห็นคนอยู่ใกล้) | มองขึ้น เลิกคิ้ว มี "!" |

- ถ้าทำท่าระหว่างที่หุ่นยนต์กำลังตอบคำถาม หุ่นยนต์ไม่พูดแทรก แสดงแค่สีหน้า (ยกนิ้วโป้งยังบันทึกคำติชม) แบมือหยุดได้ทุกเมื่อ
- การ์ดต้องอยู่ในภาพราว 0.3 วินาที และท่าทางราว 0.7 วินาทีจึงจะนับ ถือค้างไว้นานแค่ไหนก็นับครั้งเดียว ต้องเอาลงราว 1.5 วินาทีก่อนจึงจะนับใหม่
- ท่าทางต้องเป็นท่าที่เห็นมากที่สุด (อย่างน้อย 65% ของภาพที่มีท่า) ในช่วงที่ถือ และหลังนับท่าหนึ่งแล้ว ท่าอื่นต้องรอ 1.5 วินาที มือที่กำลังเปลี่ยนท่าจึงไม่ถูกนับเป็นอีกท่า
- ท่านิ้วโป้งตรวจซ้ำด้วยตำแหน่งข้อนิ้ว 21 จุด จึงแยกขึ้น/ลงได้แม่นกว่าป้ายของโมเดล ถ้าไม่เจอมือในภาพเต็ม จะขยายดูบริเวณตัวคนที่ใกล้ที่สุดอีกครั้ง
- ท่าทางนับเฉพาะเมื่อมีผู้ใช้อยู่ในบริเวณให้บริการ เพื่อไม่ให้มือของคนเดินผ่านสั่งงานหุ่นยนต์ ส่วนการ์ดนับเสมอ
- **คำติชมคำตอบ:** หลังแต่ละคำตอบ หน้าจอมีปุ่ม "ช่วยได้" / "ยังไม่ตรง" ด้วย คำตอบหนึ่งให้คะแนนได้ครั้งเดียว ดูผลได้ที่ Admin → ประวัติ (`feedback.up`, `feedback.down` พร้อมที่มาของคำตอบ) ไม่บันทึกข้อความคำถาม
- การตรวจจับทำในโปรเซสของกล้อง ราว 5 ครั้งต่อวินาที ครั้งแรกจะดาวน์โหลดโมเดลท่าทางราว 8 MB ไปที่ `models/mediapipe` ถ้าดาวน์โหลดไม่ได้ การ์ดยังใช้ได้ตามปกติ
- ดูสิ่งที่กล้องจำได้ล่าสุดได้ที่ Admin → กล้อง (ใช้ตรวจการ์ดที่พิมพ์มาใหม่) ปิดทั้งหมดด้วย `VISION_SIGNS=false` หรือปิดเฉพาะท่าทางด้วย `VISION_GESTURES=false`

กล้องเปิดได้ทีละโปรแกรม ถ้าภายหลังให้คอมพิวเตอร์ ROS ของหุ่นยนต์เป็นผู้ใช้กล้อง (เพื่อหลบสิ่งกีดขวาง) ต้องเปลี่ยนแหล่งข้อมูลใน `vision/` ให้รับตำแหน่งคนจาก ROS แทน ส่วนอื่นของโปรแกรมไม่ต้องแก้

## คำสั่งหุ่นยนต์ด้วยเสียง และกฎระยะปลอดภัย

รุ่นนี้ทำงานกับ **หุ่นยนต์จำลอง** (`MockRobotAdapter`) ยังไม่มีมอเตอร์ตัวใดขยับจริง ชื่อท่าและระยะปลอดภัยเป็นค่าตั้งต้นที่ต้องปรับเมื่อได้ข้อมูลฐานจริงจากทีมหุ่นยนต์

**สั่งได้สามทาง** ซึ่งทุกทางผ่านด่านตรวจ `CommandGateway` เดียวกัน: พูด, พิมพ์ในช่องคำถาม, หรือแตะปุ่มในหน้าสนทนา

| พูดว่า | หุ่นยนต์ทำ |
| --- | --- |
| "หันซ้าย", "หันขวา" | หันอยู่กับที่หนึ่งจังหวะ |
| "หยุด" | สั่งหยุดทันที |

**หุ่นยนต์ไม่เดิน และยังไม่มีแขน** ไม่มีคำสั่งเดิน พาไป ไหว้ โบกมือ หรือยกแขนในระบบ คำขอเหล่านี้จะถูกตอบเป็นคำถาม และหุ่นยนต์บอกทางด้วยคำพูดจากข้อมูลที่มี เมื่อติดตั้งแขนแล้ว ต้องเพิ่มท่าใน `app_config.json` พร้อมชนิด `part` ใหม่และระยะปลอดภัยของแขนกลับเข้ามา

- **ไม่ใช้ AI ตีความคำสั่ง** โปรแกรมจับคำสั่งด้วยกฎตายตัวใน `services/command_intent.py` ผลลัพธ์เป็นได้เฉพาะคำสั่งหยุดและท่าที่อยู่ใน `config/app_config.json` ข้อความที่ไม่ใช่คำสั่งชัดเจนจะถูกตอบเป็นคำถามตามปกติ
- **เพิ่มคำที่ผู้ใช้พูด** ได้ที่ `phrases` ของแต่ละรายการใน `app_config.json` (เช่นตัวสะกดที่โปรแกรมถอดเสียงมักเขียน) และระบุ `part` ของแต่ละท่าเป็น `base` หรือ `none` เพื่อบอกว่าท่านั้นขยับส่วนไหน
- **ท่าทักทาย:** ตอนนี้ `greet_action` เป็น `""` หุ่นยนต์ทักทายด้วยคำพูดอย่างเดียว ถ้าใส่ id ของท่าลงไป หุ่นยนต์จะทำท่านั้นประกอบคำทักทาย
- ปิดการสั่งด้วยคำพูดได้ด้วย `ROBOT_VOICE_COMMANDS=false` (ปุ่มบนจอยังใช้ได้)
- ขณะหุ่นยนต์กำลังพูด ไมโครโฟนปิดอยู่ จึงพูดว่า "หยุด" แทรกไม่ได้ ให้แบมือให้กล้อง หรือกดปุ่ม **หยุดหุ่นยนต์**

**กฎระยะปลอดภัย** (`robot/safety.py`) ใช้ระยะคนจากกล้อง OAK-D:

1. ก่อนเริ่มขยับ: การหันถูกปฏิเสธถ้ามีคนใกล้กว่า `ROBOT_BASE_CLEARANCE_M` (0.6 ม.)
2. ถ้าคำสั่งมาจากผู้ใช้ หุ่นยนต์ไม่ปฏิเสธเฉย ๆ แต่ขอให้ถอยหนึ่งก้าว แล้วทำเมื่อพื้นที่ว่าง ถ้ารอ 10 วินาทีแล้วยังไม่ว่างจึงยกเลิก
3. ระหว่างขยับ: ตรวจทุก 0.1 วินาที ถ้ามีคนเข้ามาในระยะจะสั่งหยุดทันที
4. ถ้ากล้องยังไม่พร้อมหรือค้าง: ปฏิเสธทุกคำสั่งที่ทำให้ขยับ (ไม่รู้ = ไม่ปลอดภัย)

ดูระยะคนที่ใกล้ที่สุดและสถานะกฎนี้ได้ที่ Admin → หุ่นยนต์

> **ข้อจำกัดของกฎนี้:** เป็นการป้องกันชั้นซอฟต์แวร์จากกล้องตัวเดียวที่มองไปข้างหน้า ไม่เห็นคนด้านข้างหรือด้านหลัง ไม่เห็นเด็กเล็กหรือสิ่งของที่โมเดลตรวจไม่พบ และมีความหน่วงจากกล้อง หุ่นยนต์จริงยังต้องมีกันชนหรือเซนเซอร์รอบตัว และปุ่ม Emergency Stop ทางฮาร์ดแวร์ ถ้าตั้ง `VISION_ENABLED=false` กฎนี้จะไม่ทำงานเลย จึงไม่ควรปิดกล้องเมื่อใช้กับหุ่นยนต์จริง

## หน้าจอผู้ใช้

หน้าจอผู้ใช้และหน้า Admin เป็นธีมมืด สีและขนาดทั้งหมดอยู่ใน `ui/styles/theme.qss` (ส่วน `#adminScreen` คือคอนโซลผู้ดูแล ส่วน `#userScreen` คือหน้าจอผู้ใช้) ด้านล่างหน้าจอผู้ใช้มีข้อความแจ้งความเป็นส่วนตัว (PDPA) ซึ่งแก้หรือปิดได้ที่ Admin → ตั้งค่าหน้าจอ

## โหมดผู้ดูแล (Admin)

กดปุ่ม **ผู้ดูแล** มุมขวาบน ครั้งแรกระบบจะให้ตั้งรหัสผ่าน (อย่างน้อย 8 ตัวอักษร) — **ตั้งรหัสผ่านก่อนนำเครื่องไปวางในพื้นที่สาธารณะ**

หน้า Admin มีเมนูด้านซ้ายแบ่งเป็น 4 กลุ่ม แถบด้านบนแสดงเวลา สถานะหุ่นยนต์ และโหมด AI ตลอดเวลา หน้าที่มีปุ่ม "บันทึก" จะถามก่อนเปลี่ยนหน้าถ้ายังไม่ได้บันทึก

| SYSTEM | ตั้งค่าหน้าจอ | รูปแบบหน้าแรก (สื่อหรือภาพกล้อง), ข้อความต้อนรับ, เวลาแสดงรูปภาพ/ประกาศ, ข้อความแจ้งความเป็นส่วนตัว |
| | สำรองและย้ายข้อมูล | สำรองฐานข้อมูล, **ส่งออก/นำเข้าการตั้งค่าเป็นไฟล์ .json** เพื่อติดตั้งหุ่นยนต์ตัวอื่นให้เหมือนกัน (ไม่มีรหัสผ่านและ API key) |
| | ประวัติการทำงาน / Log | ประวัติการทำงาน (ตาราง `activity_logs`) และ log ของโปรแกรม |
| | ความปลอดภัย | เปลี่ยนรหัสผ่าน, **เปลี่ยน/ทดสอบ/ลบ API key ของ Gemini** (เขียนลง `.env` มีผลทันที ไม่แสดงเต็มและไม่ลง log), ปิดโปรแกรม |

- **ค่าที่ปรับจากหน้าเสียงและกล้องมีผลทันทีโดยไม่ต้องเปิดโปรแกรมใหม่** ค่าใน `.env` (`TTS_SPEED`, `MIC_*`, `VOICE_FOLLOW_UP`, `VISION_*_DISTANCE_M`, `VISION_*_SECONDS`, `VISION_LATERAL_LIMIT_M`, `VISION_AUTO_LISTEN`) เป็นค่าเริ่มต้น ค่าที่บันทึกจาก Admin เก็บในฐานข้อมูลและใช้แทน จนกว่าจะกด "คืนค่าเริ่มต้นจาก .env"
- ระยะกล้องต้องเรียงจากใกล้ไปไกล: ระยะสนทนา ≤ ระยะทักทาย < ระยะที่ถือว่าเดินออก ระบบไม่ยอมบันทึกถ้าไม่เรียงกัน

- สื่อที่รองรับ: วิดีโอ `.mp4 .m4v .mov .webm .mkv .avi` (ไม่เกิน 500 MB) รูปภาพ `.png .jpg .jpeg .gif .bmp .webp` (ไม่เกิน 20 MB) ปรับเพดานได้ใน `.env`
- ไฟล์ที่อัปโหลดถูกตรวจนามสกุล ขนาด และลายเซ็นของเนื้อหาไฟล์ แล้วคัดลอกเข้า `media/` ด้วยชื่อที่ระบบสร้างเอง ฐานข้อมูลเก็บเฉพาะ metadata
- รหัสผ่านเก็บเป็น scrypt hash ในตาราง `admin_users` ใส่ผิด 5 ครั้งจะล็อก 60 วินาที โหมด Admin อยู่จนกว่าจะกดออก (ค่าเริ่มต้น `ADMIN_IDLE_TIMEOUT_S=0`) ตั้งเป็นจำนวนวินาทีถ้าต้องการให้ออกเองเมื่อไม่มีการใช้งาน — **ถ้าวางเครื่องในที่สาธารณะ อย่าลืมกดออกจาก Admin ทุกครั้ง**
- ลืมรหัสผ่าน: ปิดโปรแกรมแล้วรัน `.\.venv\Scripts\python.exe -c "import sqlite3; c=sqlite3.connect('data/app.db'); c.execute('DELETE FROM admin_users'); c.commit()"` จากนั้นเปิดโปรแกรมและตั้งรหัสใหม่
- เมื่อไม่มีใครใช้งานครบเวลา หน้าจอจะกลับไปหน้าแรก ซึ่งเล่นสื่อประชาสัมพันธ์ต่อ
- หน้าต่างเปิดแบบขยายเต็มจอ (maximized) กด `F11` เพื่อสลับโหมด fullscreen

## สถาปัตยกรรมโดยย่อ

```text
ui/  (PySide6 widgets)
  │  Qt signals เท่านั้น — UI ไม่เรียก service ที่ block และไม่เขียน SQL
  ▼
app/ VisionController ─ timer ─▶ vision/OakVisionSource ◀─ pipe ─ โปรเซสกล้อง (vision/oak_worker)
        └─ vision/PresenceTracker ─▶ "มีผู้ใช้เข้ามา" / "ผู้ใช้เดินจากไป"
app/ VoiceController ─ timer ─▶ audio/MicrophoneService + Endpointer
        └─ worker ─▶ audio/SpeechToTextService (faster-whisper, โหลดโมเดลครั้งเดียว)
        └─ ข้อความที่ถอดได้ ─▶ ConversationController.ask()
app/ ConversationController ─ worker ─▶ services/ConversationService
        ├─ ai/knowledge_service (คัดข้อมูลของเรา) ─▶ ai/GeminiClient ─▶ Gemini
        └─ app/SpeechController ─ worker ─▶ audio/TextToSpeechService ─▶ services/AudioPlaybackService
        └─ ทุกคำตอบ ─▶ services/AnalyticsService ─▶ ตาราง interactions / visits
app/ ScheduleController ─ timer ─▶ services/schedule_service ─▶ ประกาศบนหน้าแรกเมื่อหุ่นยนต์ว่าง
app/ ContentController ─────────────▶ database/repositories ─▶ SQLite (data/app.db)
        └─ worker ─▶ services/MediaService ─▶ โฟลเดอร์ media/
app/ RobotController ─────── worker ─▶ robot/CommandGateway ─▶ robot/RobotAdapter (Mock)
```

- `robot/`, `services/`, `ai/`, `database/`, `audio/`, `vision/`, `admin/`, `config/` เป็น Python ล้วน ไม่ import Qt — ทดสอบได้โดยไม่ต้องเปิด GUI
- SQL ทั้งหมดอยู่ใน `database/repositories.py`
- ทุกคำสั่งหุ่นยนต์ต้องผ่าน `CommandGateway.submit()` ซึ่งรับเฉพาะ id ที่อยู่ใน allowlist ไม่รับพิกัดอิสระ และถามกฎระยะปลอดภัยก่อนส่งถึงหุ่นยนต์
- คำพูดของผู้ใช้กลายเป็นคำสั่งได้ทางเดียว: `services/command_intent` (กฎตายตัว) → `app/CommandController` (ถามยืนยัน, ขอให้ถอย) → `CommandGateway` คำตอบของ Gemini ไม่อยู่ในเส้นทางนี้
- ปุ่ม **หยุดหุ่นยนต์** เรียก `adapter.stop()` ตรงจาก GUI thread ไม่ผ่าน AI, TTS, อินเทอร์เน็ต หรือคิวงาน

> **ความปลอดภัย:** ปุ่มหยุดในโปรแกรมเป็นเพียงคำสั่งซอฟต์แวร์ ไม่สามารถทดแทนวงจร Emergency Stop ทางฮาร์ดแวร์ได้ หุ่นยนต์จริงต้องมีปุ่มหยุดฉุกเฉินที่ตัดกำลังมอเตอร์โดยไม่ขึ้นกับซอฟต์แวร์นี้

## Log และการสำรองข้อมูล

- Log อยู่ที่ `logs/app.log` หมุนไฟล์อัตโนมัติ (2 MB × 5 ไฟล์)
- สำรองฐานข้อมูลขณะโปรแกรมทำงานได้จาก Admin → สำรองและย้ายข้อมูล → "สำรองฐานข้อมูลตอนนี้" ไฟล์จะอยู่ใน `data/backups/`
- สำรองทั้งระบบ: คัดลอกโฟลเดอร์ `data/`, `media/` และไฟล์ `config/app_config.json`, `.env` (ฐานข้อมูลอ้างชื่อไฟล์ใน `media/` จึงต้องสำรองคู่กัน) โฟลเดอร์ `models/` ไม่ต้องสำรอง ดาวน์โหลดใหม่ได้
